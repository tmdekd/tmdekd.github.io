retrospective:
  sections:
    - title: 역할과 기여
      body: >-
        요리왕 좌룡 프로젝트에서 나는 팀장은 아니었지만, 설계와 구현의 공백을 메우는 역할을 자발적으로 맡아 프로젝트에 참여했다.
        일부 팀원들의 참여도가 고르지 않은 상황에서도, 끝까지 완성도 있는 결과물을 만들어내기 위해 적극적으로 의견을 제시하고 구현에 시간을 투자했다.
        특히 파인튜닝, 데이터 전처리, 응답 구조 설계 과정에서 단순히 주어진 역할을 수행하는 데 그치지 않고, "이 구조가 실제로 사용자에게 의미가 있는가"를 기준으로 문제를 제기하고 개선 방향을 제안했다.
        그 과정에서 자연스럽게 기술적 의사결정에 관여하며 프로젝트의 완성도를 높이는 데 기여할 수 있었다.
    - title: 응답 구조에 대한 고민
      body: >-
        이번 프로젝트에서 가장 인상 깊었던 경험은 Fine-Tuning과 RAG를 무작정 결합하면 오히려 모델이 혼란스러워질 수 있다는 점을 직접 체감한 것이다.
        처음에는 두 방식을 함께 사용하면 정확도가 올라갈 것이라 기대했지만, 실제로는 응답의 일관성이 깨지는 문제가 발생했다.
        이를 해결하기 위해 각 방식을 독립적인 실행 경로로 분리하고, 응답의 적절성을 기준으로 다음 단계를 판단하는 구조로 수정했다.
        이 경험을 통해 모델 성능 자체보다도, 언제 어떤 정보를 쓰고 언제 멈춰야 하는지를 설계하는 것이 더 중요하다는 관점을 얻었다.
    - title: 실행 가능한 서비스
      body: >-
        요리왕 좌룡은 단순한 레시피 추천 챗봇이 아니라, 사용자의 현실적인 제약을 고려한 실행 가능한 AI 서비스를 목표로 했다.
        유튜브 자막 기반 데이터 수집, RAG 파이프라인 구성, API 사용량 제한 문제 해결, 프롬프트 구조 개선까지의 과정은 단순한 실습을 넘어 실제 서비스 환경을 고민하는 경험이었다.
        특히 OpenAI API 제한 문제를 CSV 분할과 요청 딜레이로 해결하고, 프롬프트가 의도대로 동작하지 않던 문제를 반복적인 수정으로 개선하면서, 문제 해결은 기술 스택보다도 구조 이해와 집요함에서 나온다는 점을 다시 한 번 느꼈다.
